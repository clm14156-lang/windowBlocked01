# UI 视觉与间距检查标准

> 用途：供 Codex 检查界面是否符合统一设计标准。
> 检查重点：字体层级、文字颜色、Gap、Padding、交互状态连续性。

---

## 1. 字体层级标准

| 类型 | 字号 | 字重 |
|---|---:|---:|
| 核心数字 | 28–32px | 600 |
| 页面标题 | 24px | 600 |
| 弹窗标题 | 18px | 600 |
| 分组标题 | 16px | 600 |
| 内容标题 | 14px | 500 |
| 正文 | 12px | 400 |
| 辅助信息 | 11–12px | 400 |

### 检查规则

- 同一层级的文字，字号和字重必须统一。
- 页面标题不能和正文、辅助信息使用相同视觉权重。
- 核心数字必须明显高于普通正文和标题中的次要信息。
- 不要因为某个区域空间更大，就随意放大字体。
- 标题和说明文字必须有明显层级差异。

---

## 2. Gap / 元素之间的间距

Gap 指两个不同元素之间的距离。

例如：

- 标题和说明文字
- 两个输入框
- 图标和文字
- 两个设置项
- 两个模块

### 常用 Gap

| Gap | 使用场景 |
|---:|---|
| 4px | 关系非常近，例如标题和紧跟的小说明 |
| 8px | 同一个小组，例如图标和文字 |
| 12px | 普通控件之间 |
| 16px | 两个项目之间 |
| 24px | 两个模块之间 |
| 32px | 两个大区域之间 |

### 检查规则

- 相同关系的元素应使用相同 Gap。
- 不要出现 7px、13px、19px、27px 等无规律间距，除非有明确理由。
- 元素之间不能过挤，也不能出现无意义的大块空白。
- 越相关的内容，距离应该越近。
- 越不相关的内容，距离应该越远。

---

## 3. Padding / 容器内部边距

Padding 指内容与容器边缘之间的距离。

例如：

- 按钮文字不能贴着按钮边缘。
- 卡片内容不能贴着卡片边缘。
- 弹窗内容不能贴着弹窗边缘。

### 常用 Padding

| 类型 | 建议值 |
|---|---|
| 小标签 | 6–8px |
| 按钮 | 上下 8–10px，左右 12–16px |
| 卡片 | 16–20px |
| 弹窗 | 24–32px |

### 检查规则

- 内容不能贴边。
- 同类型组件的 Padding 必须统一。
- 按钮可以宽度不同，但内部 Padding 规则应保持一致。
- 超宽按钮可以使用固定宽度或 `width: 100%`，左右 Padding 仍保持 12–16px。
- 不要为了让按钮变宽而随意扩大内部 Padding。

---

## 4. 文字颜色标准

| 类型 | 颜色 | 用途 |
|---|---|---|
| 主文字 | `#1D1D1F` | 页面标题、重要数字 |
| 次级文字 | `#6E6E73` | 描述、普通辅助信息 |
| 弱化文字 | `#86868B` | 日期、单位、次要说明 |
| 很弱文字 | `#A1A1A6` | Placeholder、低优先级状态 |
| 禁用文字 | `#B8B8BD` | Disabled、不可操作 |

### 检查规则

- 同一语义层级使用统一颜色。
- 重要信息不能使用过浅的灰色。
- Placeholder 不能和正文一样深。
- Disabled 状态必须明显弱于正常状态。
- 不要随意新增相近但不一致的灰色值。

---

## 5. Hover / Pressed 状态连续性

交互状态之间必须连续、协调。

常见状态：

1. Default / 普通状态
2. Hover / 鼠标悬停状态
3. Pressed / 按压状态

### 核心原则

- Default → Hover → Pressed 应该是连续变化。
- Hover 和 Default 的差异不能过大。
- Pressed 应该是在 Hover 基础上的轻微加深或加强。
- 不要让三个状态看起来像三个不同组件。
- 状态变化优先使用：
  - 背景颜色轻微变化
  - 描边颜色轻微变化
  - 文字颜色轻微变化
- 不建议同时大幅改变背景、描边、文字、阴影和尺寸。

### 错误示例

- Default 是白色，Hover 突然变成深橙。
- Hover 和 Pressed 色差过大。
- Pressed 改变按钮尺寸或圆角。
- Hover 后整体视觉重量突然增加很多。

### 推荐逻辑

```text
Default
↓ 轻微变化
Hover
↓ 再轻微加深
Pressed
```

视觉应该连续，而不是割裂。

---

## 6. Selected 与 Hover / Pressed 的关系

Selected 是“是否被选中”的状态。

Hover 和 Pressed 是“当前是否正在交互”的状态。

它们不是同一层级。

正确理解：

```text
未选中
├─ Default
├─ Hover
└─ Pressed

已选中
├─ Default
├─ Hover
└─ Pressed
```

### 检查规则

- Selected 必须比普通 Hover 更稳定、更明确。
- Hover 只是在当前状态基础上的轻微反馈。
- Pressed 是当前状态基础上的进一步按压反馈。
- Selected 不应该因为没有 Hover 而显得比 Hover 更弱。

---

## 7. Codex 检查要求

检查界面时，请逐项判断是否符合以上标准。

### 必须检查

- [ ] 字体大小是否符合层级标准
- [ ] 字重是否符合层级标准
- [ ] 同层级文字是否统一
- [ ] 主文字、次级文字、弱化文字颜色是否正确
- [ ] Gap 是否主要使用 4 / 8 / 12 / 16 / 24 / 32px
- [ ] 同类元素之间的 Gap 是否一致
- [ ] 按钮 Padding 是否合理
- [ ] 卡片 Padding 是否合理
- [ ] 弹窗 Padding 是否合理
- [ ] 内容是否存在贴边问题
- [ ] Default / Hover / Pressed 是否连续
- [ ] Hover 与 Pressed 是否存在过大色差
- [ ] Selected 与 Hover / Pressed 是否逻辑混乱
- [ ] 是否存在同类组件视觉规格不统一的问题

## 9. 总原则

检查时优先保证：

1. **统一**
2. **层级清楚**
3. **间距有规律**
4. **内容不贴边**
5. **交互状态连续**
6. **颜色变化克制**
7. **同类组件不要各自一套规则**

如果某个数值不在标准内，但有明确的布局原因，可以标记为“合理例外”，不要机械判错。
