# 准备页面进入专注页面

本次优化保留原有设计、原生 WPF Storyboard、CubicEase 和 420ms 总时长，只调整准备工作与动画的衔接。

- 准备进度达到 98% 时，以 Dispatcher Background 优先级生成一次当前窗口 DPI 的旧页截图；入场复用该冻结位图，避免在动画启动点渲染整页。截图不提前覆盖界面，准备圆环继续正常运行。
- 窗口尺寸或 DPI 变化会使截图失效；未完成预捕获时仍回退到切换前捕获，保持正确画面。取消准备、换数据上下文、隐藏、最小化、卸载和动画完成时清理截图与待执行操作。
- 新页各入场元素先设为起始状态，保持旧页截图不透明。等待最新问候文案和绑定、首次布局完成后，才开始动画；等待期间专注引擎和屏蔽启动正常执行。
- 旧页在 0–220ms 淡出，背景在 0–420ms 淡入；问候从 80ms、倒计时从 100ms、角色与阴影/天气/页脚从 120ms、目标名称从 160ms 开始淡入，各自在 420ms 结束。角色保持原有 8 DIP 入场位移及独立呼吸动画。
- 动画继续只修改 Opacity 与 RenderTransform，不逐帧修改布局属性，不创建新窗口或重新创建页面。
- 准备圆环保留 16ms 刷新；普通和服务托管专注进入后统一为 250ms 刷新。时间仍按原 Stopwatch 或服务绝对时间计算，不按 Tick 次数累计；固定总时长只在变化时发属性通知。

回归覆盖：两套主题、最新配置与默认文案、取消/重入、截图复用与尺寸失效、动画交叠、隐藏/卸载回收、真实 Dispatcher 定时、时间边界主题切换和原布局。

专项 WPF 测试验证行为与时序，不代表实际设备持续达到 60 FPS。帧率验收仍需在目标设备上比较首次/再次进入、不同 DPI 和历史数据量，记录截图、首次布局、服务状态应用及呈现帧时间；单帧预算为约 16.7ms。本次未据推测改写数据库、屏蔽服务或统计数据刷新架构。
