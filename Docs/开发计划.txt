# 开发计划

## 1. 开发原则

开发顺序固定为：

> **UI 与交互 → 业务功能 → 真实数据 → 联调测试 → UI 精修 → 发布**

执行规则：

* 一个阶段完成后再进入下一阶段。
* 每个阶段拆成模块，一次只开发一个模块。
* 当前模块验收完成后再开发下一个。
* 前期缺少 Icon、图片等资源时统一使用占位资源。
* 不提前实现后续阶段内容。

---

## 2. 阶段一：工程基础

建立最小可运行项目：

* 创建项目结构。
* 建立基础导航、资源和模块边界。
* 软件能够正常启动和运行。

不开发具体业务功能。

---

## 3. 阶段二：UI 与交互

先把整个软件的前端做通。

包括：

* 页面、弹窗、悬浮窗口。
* 点击、Hover、选中、切换、拖拽等交互。
* 页面之间的完整操作流程。
* 使用假数据和占位资源模拟真实状态。

### 完成标准

> 用户已经可以把整个软件“操作一遍”，但功能暂时不真正执行。

---

## 4. 阶段三：业务功能

在已经稳定的 UI 上实现真实功能逻辑。

包括：

* 专注与倒计时。
* 网站和程序屏蔽。
* 目标与任务。
* 自动屏蔽。
* 统计计算。
* 强制模式等核心业务。

本阶段重点是让功能真正工作，暂时可使用内存数据或模拟数据源。

---

## 5. 阶段四：真实数据

把前面的模拟数据全部替换为真实数据。

包括：

* 本地数据库。
* 设置和记录持久化。
* 数据保存与恢复。
* Service / Agent 数据。
* 账号、会员、服务器 API。
* 云端同步。

最终打通：

> **UI → 业务逻辑 → 本地数据 / Service → 服务器**

---

## 6. 阶段五：联调与稳定性测试

检查整个软件：

* 所有模块数据是否一致。
* UI 与业务是否正确联动。
* 重启、异常退出后是否正常恢复。
* 屏蔽、专注、数据库、账号、同步是否稳定。
* Windows 10 / 11、不同 DPI 和显示器环境是否正常。

发现问题逐个修复。

---

## 7. 阶段六：UI 精修

核心功能稳定后再统一处理：

* 正式 Icon、图片、主题资源替换。
* 字体、间距、圆角、颜色统一。
* 动画、Hover、Toast 等细节。
* 不同分辨率和 DPI 适配。

原则：

> **只精修视觉，不重新设计业务逻辑。**

---

## 8. 阶段七：发布

完成：

* 安装、升级、卸载测试。
* 发布包检查。
* 最终回归测试。
* Windows 正式版本发布。

---

## 核心流程

> **先做 UI 和交互 → 再做业务 → 再接真实数据 → 联调 → 精修 → 发布。**

每个阶段内部：

> **拆模块 → 开发一个 → 验收一个 → 再做下一个。**
