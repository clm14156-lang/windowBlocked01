# 已完成的任务弹窗

弹窗固定为 460 × 500 DIP（WPF 的逻辑像素），在原 800 × 710 窗口内居中展示。保留白底、14 DIP 圆角、浅灰描边和极轻阴影。标题为「已完成的任务」，遵循统计页 18 / 600 字体规范；内部左右边距 22 DIP，标题、筛选栏和表头固定，只让列表内部滚动。

顶部删除横向筛选按钮组，改为原生 ComboBox 的紧凑下拉菜单「全部／今天／本周／本月」。右侧搜索框带线性搜索图标和「搜索任务...」提示，筛选与搜索高度均为 32 DIP，最右侧显示动态「共 X 项」。选项采用浅灰 hover／选中态及右侧勾选，保持键盘选择、Esc 收起菜单和点击外部收起；Esc 在菜单已收起时关闭弹窗。

`SearchQuery` 通过 `UpdateSourceTrigger=PropertyChanged` 实时更新，仅在现有真实已完成任务投影上按任务名称执行不区分大小写的子串匹配，忽略查询两端空白。搜索与时间筛选、完成时间排序组合使用；无匹配时显示「没有匹配的任务」。空查询沿用原有无任务／时间范围无结果提示。同一目标的数据刷新保留查询、筛选与排序，更换目标或重新打开弹窗清空搜索，恢复全部和时间降序。搜索不匹配备注或子任务，也不修改源任务、完成状态、目标页统计或历史专注记录。

列表只有固定表头「任务内容／完成时间」，每个已完成父任务为一条 40 DIP 高的独立行，包含 18 DIP 橙色方形完成标记、13 / 400 任务名称和 12 / 400 本地完成时间；行间使用极浅灰分割线。完成时间预留 116 DIP，长任务名称在剩余宽度内省略并可悬停查看完整名称。备注和子任务仍保留在原始数据中，列表不额外展开层级。

数据继续来自当前目标下的真实已完成任务，经 TaskCompletionPolicy 校验并按任务 ID 去重。弹窗数量为搜索与时间范围共同筛选后的结果数量；目标页已完成任务卡片与 SummaryDisplay 仍使用全部任务总数。

时间范围使用现有本地时钟提供器：今天按本地零点到次日零点，本周按周一零点到下周一零点，本月按自然月边界，均为左闭右开区间。以 CompletedAtUtc 转成本地时间后判断，不使用创建日期或更新时间代替。缺少完成时间的旧任务仍出现在全部中，时间显示「—」，不加入有日期范围的筛选；在两种排序方向中均置于末尾。

点击「完成时间」表头切换时间升序／降序，箭头与提示文字同步更新。排序比较完整时间戳，显示精度为分钟；同一时间按原任务顺序和 ID 稳定排列。搜索、筛选或排序后列表回到顶部；修改搜索、筛选、排序、刷新数据或关闭弹窗时同步关闭任务右键菜单，避免容器回收后操作旧记录。

悬停任务行时整行使用浅灰背景，隐藏右侧完成日期并显示「···」按钮；鼠标移开后恢复日期。点击按钮打开白底圆角、轻阴影的菜单，包含带恢复图标的深色「恢复任务」和带垃圾桶图标的红色「删除任务」，两项之间使用浅灰分割线。菜单展开期间保持当前行悬停背景及按钮可见，仅该行进入菜单状态。菜单直接锚定「···」按钮，以按钮真实尺寸及坐标定位，扣除阴影留白后让菜单可见边缘与按钮右侧对齐，间隔 2 DIP 向下展开；下方空间不足时紧邻按钮向上展开，整体限制在弹窗边界内。保留任务行右键、键盘菜单键和 Shift+F10 入口；点击外部、按 Escape、滚动列表、修改搜索／筛选／排序、刷新数据或关闭弹窗时收起菜单并恢复日期。

恢复仅清除父任务的完成状态及完成时间，保留名称、目标、备注和子任务的 ID、关系及各自完成状态，使其重新进入专注 ToDoList；删除直接移除任务并同步保存。继续使用原有 MutationHandler、原始任务及子任务数据、并发保护和失败反馈，不改变专注计时或已保存的专注记录。关闭按钮、Esc 和点击遮罩关闭沿用现有交互；菜单打开时 Escape 优先收起菜单。

列表保持 WPF 原生回收式虚拟化与像素滚动。验证覆盖 240 项记录、组合筛选、实时搜索、升降序、动态数量、长名称省略、固定表头、独立滚动、键盘收起、重新打开重置，以及原有恢复／删除、保存失败回滚和专注任务一致性。隔离验证记录只用于 `.verify/completed-tasks-compact` 下的检查与原生渲染预览，应用没有内置设计稿演示任务。

原生检查包含 800×710／900×760 窗口、240 项虚拟化列表、下拉选项 UI Automation 选择、行悬停与移开、菜单保持状态、顶部向下与底部向上弹出、弹窗边界、恢复／删除菜单实际点击，以及搜索、组合筛选和空状态。恢复后专注 ToDoList、子任务关系、保存失败回滚与其他目标数据均通过原有数据流程验证。
